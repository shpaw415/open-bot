# Product reports

A queue of findings about open-bot itself, filed by the desktop agent while it works. The in-container agent is not a coding agent — but it stress-tests the product and reports what breaks.

## Filing

Every desktop can file:

```sh
ob-improve add --kind bug|friction|feature \
  --surface chat|desktop|nav|cron|persona|config|other \
  --title "Composer loses draft on tab switch" \
  --detail "Steps to reproduce..." [--session ID] [--plugin SLUG]
```

Rows land in the control-plane sqlite. Review keeps working the same way.

## Issue routing

A new report also becomes a GitHub issue, routed marketplace-first. The control plane relays it to the marketplace's `POST /api/issues` endpoint, which dedupes repeat reports across every instance and pushes each new issue with the marketplace's own GitHub token — to the open-bot repo (marketplace `OPEN_BOT_REPO`, default `shpaw415/open-bot`), or to the referenced plugin's listing repo with `--plugin SLUG`. An issue filed at the marketplace counts as routed even when its GitHub push has not landed yet; the marketplace owns the retry. The marketplace manages its queue through admin endpoints (`GET /api/issues`, `GET/PATCH /api/issues/:id`, `POST /api/issues/:id/push`).

When the marketplace is unconfigured, unreachable, or does not list the plugin, routing falls back to a direct GitHub issue with the instance's own token (`OPEN_BOT_GITHUB_TOKEN`, target `OPEN_BOT_GITHUB_REPO` or the installed plugin manifest's `repo`). Routing never blocks filing: when every external path is down, the row stays local-only and `ob-improve` prints a `warning` naming the failures. The routed URL is stored on the row (`routed_to=github|marketplace`) and printed by `ob-improve`, `scripts/reports.ts`, and the Admin Improvements tab. Local duplicates (same kind + surface + plugin + title) bump the open row's hit count and open nothing new; a duplicate whose first filing never routed retries routing. External routing is capped at 10 attempts per user per hour.

## Reviewing

Do not process the queue unless asked. When asked:

```sh
bun scripts/reports.ts                                   # list open
bun scripts/reports.ts --filters status=open,kind=bug,surface=nav
bun scripts/reports.ts done ID --note "what changed"
bun scripts/reports.ts wontfix ID --note "why"
```

Patch clear bugs and broken friction; leave features and ambiguous items open until asked. Every shipped or rejected row gets marked with a note.

## Dashboard

The Reports entry in the Views drawer reads the same queue (filter by status/kind/surface) via `GET /api/reports`, and `PATCH /api/reports/:id` flips status + note.

<Callout type="note">
Product reports and [plugin reports](/docs/plugin-reports) are different queues: product reports describe open-bot itself; plugin reports describe a plugin under test and live as JSON files on the desktop.
</Callout>
