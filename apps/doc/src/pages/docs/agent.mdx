# Desktop agent

The desktop agent is the conversational bot living in each desktop container: **OpenCode as the runtime**, shaped by the seed `AGENTS.md`, seed skills, and any installed plugins.

## Standing behavior

From the seed AGENTS.md:

- Staff-IT work style: when asked to do something, **act** — clone, branch, commit on feature branches, push via its own GitHub identity, open PRs, run CI, fix failures. Never force-push shared `main`, never touch global git config, no destructive ops without an explicit ask.
- **OpenViking first reflex** — recall/search preferences and project facts at session start; keep the registry current; never delete durable memory without explicit confirmation.
- Skills live in OpenViking (`viking://~/skills`) and sync at session start.

## Surfaces the agent can use

| Surface | Tooling |
| --- | --- |
| Thread screen | `ob-app` (native apps), `ob-chrome` (direct navigate) → `ob-page` (DOM) → `ob-nav` (System 1) → `ob-vnc` (pixels), screenshots via control API, `ob-record` (video) |
| Projects | `ob-project`, OpenCode session per project |
| Plugins | `ob-plugin` full lifecycle |
| Background work | `ob-thread` (hidden `worker:` threads), [councils](/docs/councils), cron via `ob-cron`, long-running jobs via `ob-process` |
| Untrusted code | `ob-sandbox` (offline execution box), [sandbox threads](/docs/sandbox) (disposable containers) |
| Media | `ob-media`, automatic vault filing |
| Reporting | `ob-improve` (product), `ob-report` (plugins) |
| Decisions | `ob-system1` (System 1 model) |
| Previews | `ob-preview` + `open-bot://preview` marker |
| Skills & keys | `ob-skill` (authoring), `ob-group` (directories), `ob-api-key` (provider keys) |

## Personas

The thread's persona is locked at creation (user + OpenCode session) and injected as a system line on every prompt. Custom personas live in sqlite; built-ins cannot be edited. The agent can manage personas with `ob-persona`.

## Persona scopes

A persona can carry a **skill allowlist** and an **MCP server allowlist** — a restricted persona's threads see only the allowed skills in model context and only the listed servers' tools. Both are three-state: unset = everything, a name list = allowlist, and an explicit block-all flag (`--skills none` / `--mcp none`) denies every skill or server — the only way to do that on a locked base persona.

- **Built-ins are seed-scoped by default**: the desktop's seed skills plus owner-less MCP servers, extended per user with "Added by you" extras. The **Assistant** is the exception — it loads *every* skill (seed, plugin, custom) so it can manage integrations on its own.
- Scopes are enforced per session via OpenCode permission rules — no restarts, no config rewrites; they survive opencode restarts.
- Scope curation is organization, **not a security boundary** — the agent can still read any skill file on disk. For untrusted prompts, use a [sandbox thread](/docs/sandbox).

The dashboard persona dialog renders filterable chip pickers (grouped, with locked plugin bases); the CLI mirrors them (`--skills`/`--mcp` and their append/remove/clear variants — see [Other CLIs](/docs/ob-misc#ob-persona---personalities)).

## Autonomy-first login and human checks

The agent finishes tasks start-to-end itself and hands the screen over only when there is no other way:

- **Login** — it signs in with credentials it already knows: given in the conversation, Chrome autofill, or a live signed-in session — verifying the landing and retrying once on rejection. It never guesses, extracts, or stores passwords. Handover waits for no-known-credentials, a still-rejected retry, or a code/passkey/biometric only you hold.
- **Human checks** — a single "I'm not a robot" checkbox is the agent's own click (one re-check, second click, then it stops). Anything escalating into a puzzle, image-select, slider, or typed-characters captcha is never solved, bypassed, or bought — it goes to you with the screen marker.
- `ob-nav` follows the same line without credentials: login walls and unpassable checks surface as `needs_user`.

## Agent-side config

- `PUT /api/agent-config` sets the image / video / model-3D models the agent uses for generation.
- `GET /api/providers`, `POST /api/providers/login|logout`, `PUT /api/model`, `GET /api/models` manage chat provider auth — this is the dashboard's Config page, Providers tab. Claude Code and Muse subscriptions connect there too (see [Web dashboard](/docs/dashboard)).

## Skills

Seed skills are copied into the image at build time (`images/opencode/seed/skills/*`): apps, media, plugin, preview, project, report, system1, thread, persona, council, catalog, and more. **Existing desktops only get new seeds after `bun run images && bun run update`.**

The agent also **authors its own skills** with `ob-skill save/get/rename/delete --group` against the OpenViking-backed store — the same store the Skills tab edits, so agent-written skills appear live on the dashboard and can be grouped into directories with `ob-group`. See [Other CLIs](/docs/ob-misc).
