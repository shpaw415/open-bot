# OpenViking setup

Each desktop's OpenViking instance (the memory server on port 1933) needs an **embedding model** and a **VLM**. Every user sets their own on the **Config** page; an admin sets a fallback under **Admin → OpenViking models (default)** for users who have not saved their own.

## Prerequisites (Cloudflare Workers AI example)

- A Cloudflare account with Workers AI enabled (Workers Paid for the models below)
- An API token with Workers AI edit permission (dash.cloudflare.com → My Profile → API Tokens)
- Your Cloudflare account ID (dashboard overview, right sidebar)

## Set the models

1. Log in to the control plane.
2. Open **Config** (per user, saves to your own desktop) or **Admin → OpenViking models (default)** (account-wide fallback).
3. Pick an **Embedding provider** — the form shows only the fields that provider needs. For the Cloudflare example:

| Field | Value |
| --- | --- |
| Embedding provider | Cloudflare Workers AI |
| Cloudflare account id | your account ID (dashboard overview, right sidebar) |
| API key | your Workers AI token |
| Embed model | `@cf/qwen/qwen3-embedding-0.6b` |
| Embed dimension | `1024` |
| VLM model | `@cf/mistralai/mistral-small-3.1-24b-instruct` |

4. **Save OpenViking models** — a blank API key keeps the already-saved key.

Cloudflare needs no Base URL: the OpenAI-compatible endpoint (`https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/v1`) is derived from the account id, and model IDs keep the `@cf/` prefix. Other providers: OpenAI, Voyage AI, Cohere, Jina AI, Google Gemini, Alibaba DashScope, MiniMax and Volcengine Ark need just an API key (each with its default endpoint — an optional base URL override), Ollama and a LiteLLM proxy need their base URL, the in-container local model needs nothing, and Custom OpenAI-compatible takes any `/embeddings`-shaped endpoint. Switching the provider also retints the suggested embed dimension.

## VLM from your OpenCode setup

The form's **VLM source** can be switched from the embedding endpoint to **OpenCode model**: pick a provider and a model from the ones connected in OpenCode on your desktop (the list loads on demand, which starts a sleeping desktop), and OpenViking calls it with that setup's existing login — nothing to paste. An OpenAI **Codex subscription** works through OpenViking's native `openai-codex` backend: the control plane converts OpenCode's OAuth entry into a bootstrap auth file on every desktop start and OpenCode keeps owning token refresh. xAI (including its OAuth login), Z.AI / GLM coding plan, Anthropic, Google, OpenRouter and a few others route through OpenViking's LiteLLM/GLM backends with the desktop's stored credential (a matching Keys-tab key is the fallback). The embedding endpoint can double as the VLM endpoint only for OpenAI-compatible providers (Cloudflare, OpenAI, Ollama, LiteLLM, custom); a native embedding provider (Voyage, Cohere, …) serves embeddings only, so the VLM must come from OpenCode — the form switches and explains itself.

## Apply

Sleep the desktop, then start it again — desktop start recreates the per-user OpenViking container with the saved config passed via the `OPENVIKING_CONF_CONTENT` env var (`apps/control/src/docker.ts`, `vikingConfig`). There is no config file to manage on the host.

## Form limitations

The Admin form sends no extra fields, so it cannot set:

- `cf-aig-gateway-id` — the host `~/.openviking/ov.conf` can route embeddings through an AI Gateway (named `embeddings`) for caching and logs. Without it, requests go straight to Workers AI and still work.
- `reasoning_effort: low` for the VLM — Mistral Small answers without it.

Avoid `@cf/meta/llama-3.3-70b-instruct-fp8-fast` as the VLM: Workers AI caps it at a 24k-token context window, and OpenViking sends whole documents for abstracting, so large adds fail with HTTP 413.

## Health card

The Config memory tab leads with an **OpenViking health** section (auto-check on mount, « Check again » button): a status chip (healthy/unhealthy/up/down/asleep/starting), per-component health counts, error list, and — for the parseable components — echarts (vikingdb collection sizes, queue throughput) plus the raw status tables. OpenViking is a desktop sidecar, down by design while the desktop sleeps: an asleep or starting desktop answers without waking anything.

## Verify

```sh
curl http://127.0.0.1:8787/api/health          # {"ok":true}
```

- Start a desktop, then from inside the OpenCode container: `ov find "anything"` — results mean embeddings work.
- Ask the agent to take a screenshot — a described image means the VLM works.
